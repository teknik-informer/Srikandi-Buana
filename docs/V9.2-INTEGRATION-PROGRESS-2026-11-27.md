## Implemented in this checkpoint

### Global search

- Added `GET /api/search?q=...` as a server-only V9 operational search endpoint.
- Search requires a valid V9 identity and scopes queries to `identity.organizationId`.
- Search results are permission-gated for membership, field programs, business products, agriculture plots, Secretariat documents, and finance journals.
- External document visibility is restricted to final/public documents. Cashier catalog results are limited to active and published products.
- Search responses are marked private/no-store and do not expose member phone/address fields.
- The topbar search keeps permission-filtered navigation results and adds debounced V9 record results. It does not read browser localStorage.
- Operational search rules now live in one server-only service shared by the API and full-results page, avoiding different permission behavior between the dialog and “Lihat semua hasil”.
- The full-results page groups permission-scoped records with application/menu destinations and distinguishes an unavailable operational search from a valid empty result.
- The dialog traps keyboard focus while open, restores focus when closed, and exposes explicit loading, failure, and empty states.
- Remote results are bound to the active query so results from a previous search are not displayed under a new term.

### Quick Create

- Replaced the old shortcut-link catalogue with permission-derived form options.
- The six forms call existing V9 server actions:
  - membership interest submission;
  - agriculture plot creation;
  - field activity/agenda creation;
  - Secretariat letter registration;
  - field program creation;
  - field task creation.
- Membership submission remains an interest application. It does not create an active membership or login account; existing review and Secretariat verification remain authoritative.
- Field options are derived from enabled organization field registry entries and the active identity's server permissions.
- No browser-local demo store is used by the new quick-create component.
- All mutation forms now expose a pending state and disable repeated submission while the server action is running.

## Website Studio and public-site controls — 27 November 2026

The integration branch now includes an organization-wide public website settings editor in Studio.

- Settings are stored in the existing `v9.system_settings` row (`setting_key = 'public_site'`, `visibility = 'public'`). No schema migration was added.
- Authorized `platform_admin` and `organization_admin` users can create, edit, enable/disable and delete navigation groups, menu links, footer groups/links and social channels; configure site identity, logo, hero content, announcement, contact channels, home sections, public features, header controls, footer credit and copyright.
- Each successful save is recorded in `v9.audit_events` with before/after state. Settings are shared for the organization, not held in browser localStorage.
- Public header, search palette, home sections, contact page and footer consume the same settings record. The mobile footer uses collapsible link groups to reduce vertical scrolling.
- Public feature switches also guard direct route access. The public product feature defaults to OFF; listing, detail, order-information, navigation, search and homepage promotion follow that flag. Internal product register, inventory, orders, POS and finance workflows remain operational and permission-controlled.
- Public text was cleaned of the old demo banner, demo-login prompt, browser-local migration explanation and legacy catalogue credit. Public and internal user-facing labels use “Produk” / “Produk & Persediaan”; existing route IDs and internal module identifiers remain intact for compatibility.
- The default brand image is the transparent wordmark suited to the light public header. Contact details remain blank unless the organization enters verified channels in Studio.
