# V9.2 Login UI / V9.1 Authentication Compatibility Check

Date: 2026-11-24

## Verified

The uploaded V9.2.0 package uses the same compact responsive sign-in composition that is present in the current V9.1 operational-core branch: full-viewport photo/brand layout, concise sign-in card, Indonesian labels, and mobile-first spacing.

The current integration branch already has the production-oriented variant:
- `src/app/masuk/page.tsx` resolves `getIdentity()` from the V9.1 server session and redirects authenticated users.
- `src/components/login-form.tsx` submits email and password to the server action; it does not select a demo identity.
- `src/app/actions/auth.ts` checks `V9_HASH_PEPPER`, queries the V9 schema through `V9_DATABASE_URL`, verifies the password hash, resolves an active role assignment, and creates a hashed server-side session token.
- `src/lib/session.ts` resolves identity from the hashed server session token and active role assignment.

## Decision

Do not replace the current V9.1 login/session implementation with the V9.2 demo login form. Preserve the existing responsive visual composition and keep the production authentication contract.

## Runtime and release gate

The initial audit was performed before Preview environment configuration was completed. The current Vercel project has these two sensitive variables configured only for the Preview target and only for branch `feat/v9.2-production-integration`:
- `V9_DATABASE_URL`
- `V9_HASH_PEPPER`

The current metadata check did not decrypt or display either value and reported no hidden Production environment variables. The active Preview points to the isolated Neon QA/rehearsal branch, not the legacy Production database.

The QA database currently records 21 applied migrations (0001–0021), one active imported account marked legacy-auth-eligible, and one active `organization_admin` role assignment. A valid test password is not available to this workflow, so end-to-end login/logout has not been claimed as passed. Do not reset or replace the imported account, fabricate credentials, or run the one-time first-admin bootstrap: the QA database already contains an account, and that bootstrap is intentionally limited to an empty V9 account table.

A first-admin bootstrap on a fresh isolated database would additionally require temporary one-time values:
- `V9_BOOTSTRAP_NAME`
- `V9_BOOTSTRAP_EMAIL`
- `V9_BOOTSTRAP_PASSWORD`
- `V9_BOOTSTRAP_CONFIRM=CREATE_FIRST_ORGANIZATION_ADMIN`

Temporary bootstrap variables must be removed after success. Do not write any secret values into source control or issue comments.
